## 1. 成片規格與剪輯原則

### 1.1 建議成片規格

| 項目 | 規格 |
|---|---|
| 畫布 | 1920 × 1080，16:9 |
| 幀率 | 30 fps |
| 影片格式 | H.264 High Profile，15～24 Mbps |
| 音訊 | AAC，48 kHz，320 kbps |
| 目標長度 | 5:10～5:40 |
| 旁白語速 | 每分鐘約 230～260 個中文字；重要數據刻意停頓 |
| 響度 | 整體約 -14 LUFS，旁白峰值不高於 -1 dBTP |

現有素材高度介於 852～902 px，不可直接拉伸至 1080。統一處理方式：

1. 原畫面等比例縮放至 1920 px 寬。
2. 垂直置中於 1920 × 1080 畫布。
3. 上下空白使用 `#070B12`，或使用同畫面放大、模糊 24～32 px、亮度降至 25% 作背景。
4. 不裁掉右側決策卡、上方狀態列與下方時間軸。
5. 需要強調數字時，局部放大至 110%～125%，維持 2～4 秒後平順回到全畫面。

### 1.2 敘事原則

- 主影片只講一條事故應變主線，不把所有功能逐頁念完。
- 每個操作都回答一個問題：發生什麼、怎麼算、建議什麼、核准後改變什麼、能否驗證。
- LLM 只描述為「生成摘要與說明」；路線、門檻、指標與方案比較由程式計算。
- 不宣稱已直接控制真實號誌，統一稱為「可執行的控制建議與決策模擬」。
- 右側獨立「推演」及自然語言 What-if 不是事故主線的一部分，只能放在片尾加值蒙太奇。

## 6. 讓片段連接流暢的方法

### 6.1 以「因果」而不是以「頁面」串接

每段結尾的動作，要成為下一段開頭的原因：

| 前一鏡結尾 | 下一鏡開頭 | 串接句 |
|---|---|---|
| 官方圖層已載入 | 時間軸開始播放 | `這些資料先建立正常基準，接著讓城市時間開始推進。` |
| 指標達門檻 | 預警彈出 | `一旦超過 SOP 門檻，系統不等待人工巡查。` |
| 預警要求處理 | 注入事故 | `除了自動偵測，管理者也能注入即時事故。` |
| 事故注入完成 | 事件焦點突出 | `事故不是一個圖示，它會改變路網狀態。` |
| 影響範圍算完 | 多方案出現 | `知道影響後，下一步才是比較怎麼處理。` |
| 方案比較完成 | 人工核准 | `Agent 提案，但指揮官保有最後決策權。` |
| 方案套用 | 閉環監測 | `執行不是終點，系統仍持續觀察結果。` |
| 判定需要救援 | 雙程路線出現 | `若事故需要送醫，救援路徑同步進入規劃。` |
| 救援啟動 | 號誌滾動調整 | `救護車的位置，決定下一個被優先控制的路口。` |
| 救援進行 | 四語通知 | `道路控制之外，周邊民眾也必須同步收到行動指引。` |
| 通知完成 | 稽核證據 | `最後，每一項計算與核准都留下可追溯證據。` |

### 6.2 轉場規則

- 同一地圖、不同狀態：4～8 幀交叉溶解或直接硬切，優先保持道路位置一致。
- 不同功能章節：使用 6～10 幀暗場或單色線條 wipe。
- 操作按鈕前後：硬切，保留點擊聲，強化「按下後發生改變」。
- 手機通知：以卡片縮放／滑入處理，不使用旋轉或 3D 翻頁。
- 救護車進度跳接：以車輛位置 match cut，不使用白閃。
- 全片轉場種類不超過三種，避免像功能展示拼貼。

### 6.3 聲音串接

- 背景音樂以低頻、科技感、無人聲為主，旁白時壓低 8～10 dB。
- 警示、核准、救援啟動各使用不同但克制的 UI 音效。
- 重要轉場使用 J-cut：下一鏡旁白或提示音提前 0.15～0.3 秒進入。
- 不保留螢幕錄製中的雜音、系統通知音或滑鼠連續點擊聲，只重建必要操作音。
