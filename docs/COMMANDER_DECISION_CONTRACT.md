# 指揮官決策契約

## 指揮官畫面

每次事件固定回答五個問題：現況、影響、建議、資源／交通代價、預期改善。
沒有執行方案模擬時，改善欄必須顯示「尚未模擬」，不得用建議文字冒充效果。
所有調度、改道與推播在核准前一律標示為 `proposed`。

## 智慧號誌

下一輪採 90 秒週期，以路段作為方向代理：

`需求 = 0.35×車流容量比 + 0.25×飽和度 + 0.15×低速壓力 + 0.15×等待 + 0.10×行人需求`

各方向先保留 10–15 秒行人安全下限，再依需求占比分配剩餘秒數，單方向最多
50 秒。主辦方沒有方向排隊等待欄位，所以目前等待時間明示為由飽和度估計；
接入逐方向感測器前，不能宣稱為真實路口控制結果。

## 事件推理與方案比較

事件只改變 sandbox 路網狀態，不覆寫主辦方觀測資料：

`事件 → 規則與可信度 → 影響／路徑／ETE → 方案 A/B → 指標差異 → 人工核准`

方案包含 baseline hash、scenario hash、模型版本、公式、資料來源及限制；相同輸入能重播相同結果。

## 救護車滾動綠廊

官方號誌以 `icid` 路口群組控制：

`等待 → 行人清空 8 秒 → 下一路口優先綠 → 救護車通過 → 恢復 12 秒 → 下一路口`

不同路口任一模擬秒最多一個 `EMERGENCY_GREEN`。前端只點亮 runtime 回傳的
目前路口，不再因整條走廊核准而同時點亮所有號誌。現階段救護車位置依道路幾何
起點與推估速度播放，未連接真實車聯網定位。

## Agent 防幻覺

- Agent 工具只有唯讀查詢及不修改正式狀態的 sandbox。
- 沒有工具證據的 factual final 會被拒絕，改為「尚未取得可驗證證據」。
- SOP 引用只從實際工具軌跡產生，不再從回答文字自行擷取。
- 每次工具呼叫保存參數 SHA256、結果 SHA256、模型與 evidence validation status。
- Coordinator 與模擬結果附 `evidence_contract`：資料、規則、公式、模型、hash、限制及 claim status。
- LLM 沒有發布、號誌控制、資源調度或核准工具；高風險動作永遠需要人工核准。
